# 时间线搜索规格

## Problem Statement

浏览时间线可以展示当前打开的标签页和最近浏览记录，但用户无法用关键词缩小内容范围。时间线较长时，用户只能滚动浏览或依赖浏览器原生页面查找；后者不理解尚未渲染的节点、会话结构或标签页父子关系，也无法提供准确的匹配统计。

## Solution

在浏览时间线的标题栏中增加始终可见的搜索框。搜索扫描当前时间线快照中的全部当前标签页和最近浏览记录，按标题、域名和完整网址进行实时筛选，同时保留会话与必要的标签树上下文。结果提供命中线索、统计、分页和专用空状态，并在当前页面会话内保持查询状态。

## User Stories

1. 作为使用浏览时间线的用户，我想直接输入关键词，以便快速缩小大量浏览活动的范围。
2. 作为使用浏览时间线的用户，我想从第一个字符开始看到结果更新，以便搜索中文单字或域名首字母。
3. 作为使用浏览时间线的用户，我想搜索当前打开的标签页，以便立即切换到仍在使用的页面。
4. 作为使用浏览时间线的用户，我想搜索最近浏览记录，以便重新打开已关闭的页面。
5. 作为知道页面标题的用户，我想按标题搜索，以便凭记忆找回页面。
6. 作为知道网站域名的用户，我想按域名搜索，以便查看该网站相关的活动。
7. 作为记得网址路径的用户，我想按完整网址搜索，以便在标题含糊时仍能定位页面。
8. 作为输入英文关键词的用户，我想让搜索忽略大小写，以便不用回忆原始大小写。
9. 作为输入部分词语的用户，我想获得部分匹配结果，以便不用输入完整标题或网址。
10. 作为输入多个关键词的用户，我想要求每个关键词都在同一条记录中出现，以便逐步收窄结果。
11. 作为查看搜索结果的用户，我想保留历史记录所属的浏览会话，以便理解结果出现的时间背景。
12. 作为查看当前标签树结果的用户，我想看到匹配标签页的必要父节点，以便理解标签页的来源关系。
13. 作为查看上下文父节点的用户，我想明确知道它只是上下文，以免误以为它也匹配关键词。
14. 作为查看搜索结果的用户，我想看到可见字段中的命中词，以便快速辨识匹配原因。
15. 作为通过隐藏网址路径命中的用户，我想看到相关网址片段，以便理解该结果为何出现。
16. 作为搜索宽泛关键词的用户，我想分批加载结果，以便页面保持流畅。
17. 作为查看分页状态的用户，我想让分页只计算真实匹配项，以便显示数量准确。
18. 作为查看标签树结果的用户，我想让附带的上下文父节点不占匹配项分页名额，以便每页得到完整数量的真实结果。
19. 作为已展开普通时间线的用户，我想在清除搜索后恢复原来的展开进度，以便临时搜索不会破坏浏览状态。
20. 作为在仪表盘与时间线之间切换的用户，我想让当前查询保持不变，以便回来后继续查看结果。
21. 作为刷新时间线数据的用户，我想让当前查询保持不变并应用于新快照，以便不用重复输入。
22. 作为重新打开 Tab Out 的用户，我想看到未筛选的时间线，以免误以为记录丢失。
23. 作为查看搜索摘要的用户，我想看到匹配项数、匹配会话数和分页进度，以便理解结果规模。
24. 作为没有得到结果的用户，我想看到明确的零结果说明和清除操作，以便区分无匹配与无浏览记录。
25. 作为键盘用户，我想用 Tab 聚焦搜索框并用 Escape 清空查询，以便不依赖鼠标。
26. 作为依赖浏览器页面查找的用户，我想保留浏览器原生快捷键，以便时间线搜索不改变既有习惯。
27. 作为使用窄屏窗口的用户，我想让搜索框换行并保持足够宽度，以便仍能正常输入和阅读。
28. 作为访问过同一网址且仍保持其打开的用户，我想在当前标签树与历史会话中分别看到它，以便保留两种浏览上下文。

## Implementation Decisions

- 搜索范围是当前时间线快照，而不是全部浏览器历史；沿用时间线已有的最近活动窗口和最大记录数。
- 建立一个无 I/O 的时间线搜索模块。它通过一个公开接口接收时间线快照、查询词和分页上限，并返回筛选后的标签树、会话、命中线索及统计信息。
- 搜索模块集中承担查询规范化、按空白拆词、AND 匹配、字段匹配、标签树上下文保留、会话筛选和匹配项分页，调用方无需了解这些规则。
- 标题、域名和完整网址共同构成每条记录的可搜索文本。匹配忽略大小写并采用部分匹配。
- 多个词必须全部命中同一条记录，但可以分别命中该记录的不同字段。
- 当前标签树只保留真实匹配节点、匹配节点的后代结果以及连接它们所需的祖先。仅作为连接用途的祖先标记为上下文，不计入匹配数。
- 历史会话只保留至少一个真实匹配项的会话，并只显示其中的匹配记录。
- 可见标题和域名提供命中高亮。若匹配只来自完整网址中未显示的部分，则提供简短的网址命中线索。
- 同一网址在当前标签树和历史会话中具有不同语义，不进行跨区域去重，并分别计入匹配数。
- 普通时间线和搜索结果拥有独立的分页上限。搜索首次显示最多 200 个真实匹配项，上下文节点不占名额；清除搜索恢复普通时间线先前的展开上限。
- 搜索框在标题栏中始终可见。宽屏布局依次为标题与摘要、搜索框、刷新按钮；窄屏时搜索框占据下一行的完整宽度。
- 搜索从第一个字符开始实时执行。清除按钮和 Escape 都能清空查询；Escape 清空后保持输入焦点。
- 查询仅保存在当前页面内存中。切换视图和刷新时间线快照时保留，页面重新加载时重置。
- 搜索激活时复用标题下方摘要，展示真实匹配数、包含匹配项的会话数以及已显示数量。上下文节点不参与统计。
- 零匹配使用专用空状态，并提供清除搜索操作；它与没有最近浏览活动的空状态明确区分。
- 不接管 Cmd/Ctrl+F、斜杠或其他全局快捷键。
- 搜索不改变时间线节点的既有激活行为：已打开标签页仍切换到原标签页，历史记录仍按既有规则打开。
- 现有不相关的工作区修改必须原样保留。

## Testing Decisions

- 唯一自动化测试缝是时间线搜索模块的公开接口；测试只断言调用方和用户可观察到的返回结果，不测试内部辅助函数。
- 测试使用内存中的真实快照对象，不模拟内部协作者，也不依赖 Chrome API 或浏览器 DOM。
- 通过纵向 TDD 用例覆盖：单词与多词匹配、跨字段 AND、标签树祖先上下文、历史会话筛选、跨区域重复网址、网址命中线索、真实匹配项分页、上下文节点不占名额，以及零结果统计。
- 预期值使用独立的明确示例，不通过复制实现算法计算期望结果。
- 界面接入通过现有轻量语法检查和静态连线检查验证；不新增一套脆弱的伪浏览器 DOM 测试框架。
- 最终运行单个相关测试文件、完整测试套件以及扩展脚本语法检查。

## Out of Scope

- 搜索超过当前时间线窗口的全部 Chrome 浏览历史。
- 修改时间线的最近活动时长、最大历史记录数或会话聚类规则。
- 跨页面或跨浏览器会话持久保存搜索词。
- 接管浏览器原生页面查找快捷键或增加新的全局快捷键。
- 按日期、时间、节点状态或会话标题搜索。
- 对当前标签页和历史记录中的相同网址进行去重。
- 改变时间线节点的打开、切换、刷新或回顶部行为。
- 引入服务器、网络请求、外部搜索服务或遥测。

## Further Notes

- 浏览时间线和时间线搜索的领域含义以项目根部领域词汇表为准。
- 这些交互决策容易调整，也没有跨上下文锁定，因此不创建架构决策记录。
- 实现应沿用现有主题变量、统一面板视觉语言、委托事件处理和无内联事件处理器约束。
